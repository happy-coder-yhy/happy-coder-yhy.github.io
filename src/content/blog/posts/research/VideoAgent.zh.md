## 核心框架：把长视频变成可查询的统一记忆

VideoAgent 针对长视频端到端处理成本高、注意力难以覆盖远距离事件的问题，采用“离线构建记忆、在线工具查询”的结构。输入视频先被转换为两类记忆，LLM 再根据问题选择工具、读取结果并循环推理。

### 1. 时间记忆：保留全局事件上下文

视频被切成约 2 秒的短片段。每段使用 LaViLa 生成事件字幕，使用 ViCLIP 提取视频特征，并使用 `text-embedding-3-large` 为字幕建立文本嵌入。时间记忆因此同时包含：

- 片段字幕，用于描述“发生了什么”；
- 视频特征，用于视觉—文本相似度定位；
- 字幕特征，用于文本查询和片段检索。

时间记忆适合回答整体活动、事件顺序和粗粒度时间定位，但字幕会丢失细节，不能替代原始视频。

### 2. 对象记忆：追踪跨片段的对象状态

对象记忆由特征表和 SQL 数据库组成。RT-DETR 与 ByteTrack 先发现和追踪对象，再通过 CLIP 与 DINOv2 特征相似度把多个 tracking ID 合并为同一个 object ID。

- 特征表保存对象的视觉特征，支持“红色杯子”等自由文本检索；
- SQL 表保存 object ID、类别以及对象出现过的片段 ID；
- re-ID 解决对象在不同时间出现、姿态变化或短暂消失时的身份连续性。

这种设计把“对象是谁”和“对象在哪些片段出现过”分开存储，便于后续生成 SQL 查询。

### 3. 最小但足够的工具集合

VideoAgent 没有堆叠大量工具，而是围绕统一记忆提供四个核心接口：

- `caption_retrieval`：读取指定时间范围内的片段字幕；
- `segment_localization`：根据文字查询返回最相关的 Top-5 视频片段；
- `visual_question_answering`：让 Video-LLaVA 或 GPT-4V 检查短片段中的视觉细节；
- `object_memory_querying`：从自然语言提取对象描述，检索对象 ID，再由 LLM 编写 SQL 查询。

每轮 LLM 根据问题和历史结果选择一个工具，追加工具结果，直到决定停止并生成答案。单次字幕检索最多读取 15 个片段，避免把长视频重新塞回上下文。

### 4. 从问题到答案的闭环

系统先根据问题判断需要全局事件、时间片段、对象身份还是局部视觉细节。一个典型流程是：先用 `segment_localization` 找到“男孩和大人同时出现”的片段，再用 `visual_question_answering` 检查候选片段，最后综合多个工具结果回答关系问题。

因此，LLM 主要承担任务分解、工具选择和结果汇总；视频字幕、检索模型、对象跟踪、数据库和 VLM 分别承担可验证的子任务。

## 个人思考

### 1. 论文想解决什么问题？

核心问题是：**如何让现有视觉、语言和视频模型协作处理长视频，而不是让一个端到端模型同时记住所有事件、对象和空间关系？**

论文关注的不是单帧识别，而是长视频中跨时间的事件顺序、对象状态和多步问题。它把视频理解改写成“记忆构建 + 证据检索 + 工具推理”的任务。

### 2. 前人已有哪几类工作，痛点是什么？

- **端到端多模态 LLM**：统一性强，但长视频 token、显存和注意力成本高，远距离事件关系也可能被忽略。
- **一般多模态 Agent**：可以调用检测、VQA 等工具，但若没有视频专用记忆，工具之间容易重复读取帧，流程复杂且难以保持对象身份。
- **文本叙事或关键帧方法**：成本较低，却可能丢失局部视觉证据、时间关系和对象数量信息。

VideoAgent 的出发点是：一套小而稳定的记忆与工具接口，可能比更大的上下文和更多工具更适合长视频。

### 3. 本文用了什么创新方法解决痛点？

1. **统一记忆**：把事件级时间记忆和对象级状态记忆放在同一查询框架中，分别覆盖全局上下文与持续对象细节。
2. **对象 re-ID**：用 CLIP 与 DINOv2 的组合特征合并跨片段 tracking ID，避免同一对象被重复计数。
3. **最小工具集**：将时间检索、视觉核验和 SQL 对象查询组合起来，让 LLM 逐步收集证据。
4. **无需额外训练 Agent**：主要利用已有视频模型、VLM、嵌入模型和 GPT-4 的零样本工具调用能力，降低适配成本。

### 4. 效果怎么样？

- **EgoSchema**：在完整 5031 问题测试集上达到 60.2%，在官方 500 问题子集上达到 62.8%；接近 Gemini 1.5 Pro，并明显高于 Video-LLaVA、SeViLA 等基线。
- **Ego4D NLQ**：在零样本片段定位中，Ego4D 字幕与 ViCLIP 的组合达到 R1@0.3=17.39、R1@0.5=7.47；仍低于监督式 GroundNLQ，但优于若干零样本基线。
- **WorldQA**：Open-Ended QA 为 32.53%，Multi-Choice QA 为 39.28%。多选题超过 GPT-4V，开放问答低于 GPT-4V，说明结构化记忆有助于检索和选择，但生成答案仍受 VLM 能力影响。
- **NExT-QA**：在随机抽取的 600 问题子集上，Temporal、Causal、Descriptive 分别为 60.0%、76.0%、76.5%，平均 70.8%。这是子集结果，不能与完整验证集分数直接混比。
- **消融**：字幕检索单独已有 40.7% 平均准确率；加入对象数据库、片段定位和 VQA 后提升到 74.7%。没有 re-ID 时平均为 48.7%，没有对象数据库时为 62.7%，说明对象连续性和局部视觉核验都重要。

这些结果支持“记忆与工具协作有效”，但不同数据集使用的模型、问题规模和评测协议不同，不能把所有百分比当成一个统一排行榜。

### 5. 还有什么不足之处（未来继续深挖的点有哪些）？

- **记忆主要是离线构建的**：视频先完整切片、字幕、追踪和 re-ID，再回答问题，尚未验证在线流式场景中的低延迟更新。
- **状态不是物理状态**：对象记忆保存出现片段和视觉特征，不能可靠表达抓取、接触、遮挡后的位置变化或动作结果。
- **字幕与 re-ID 是误差源**：错误字幕会影响时间定位，视觉相似度会造成同类物体混淆；SQL 查询的可解释性不等于事实正确。
- **工具成本和隐私边界未充分报告**：使用多个外部模型、OpenAI embedding 和 GPT-4，实际调用成本、延迟和数据传输约束需要单独评估。
- **“无训练”不等于无调参**：re-ID 的组合权重在 EgoObjects 上网格搜索，工具、提示词和模型选择也会影响结果。
- **与具身记忆的距离**：后续 Embodied VideoAgent 才将深度、相机位姿和 VLM 状态更新引入动态三维场景；本文更适合作为时间/对象记忆与工具查询的基础版本。

### 6. 与当前研究的关系

VideoAgent 给“任务内情景记忆”提供了一个清晰的早期接口：时间戳、对象 ID、出现片段和工具结果。但它还没有解决我关心的证据生命周期问题：何时写入、何时失效、如何区分模型推断与真实动作后果，以及如何从多次经历验证出跨任务 skill。

一个自然的后续实验是固定视频 Agent 或具身 harness，比较普通字幕/对象记忆、带深度与时序证据的记忆、带重观察门控的记忆，并记录错误记忆持续时间、修正延迟、错误完成判断和后续迁移，而不只报告最终问答准确率。

## 局限与进一步问题

- 长视频的离线预处理会把计算成本从推理阶段转移到记忆构建阶段；
- 文本记忆能提升可检索性，却可能掩盖原始视觉证据的不确定性；
- 对象级 SQL 关系很适合查询出现历史，但不足以表示动态三维几何、接触和因果事件；
- 当前工具闭环只生成答案，没有独立的状态验证器或失败恢复机制。
